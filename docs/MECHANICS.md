# Механика оригинала и перенос

Источник: [Minecraft 26.4 Snapshot 4, 13 октября 2026](https://www.minecraft.net/en-us/article/minecraft-26-4-snapshot-4).
Поведение дополнительно сверено с байткодом локального клиента `26.4-snapshot-4.jar`, SHA-1 `ac783fa45b137dd545c7ffb76bbd595ea85fda0a`.
Исходный код Minecraft и ресурсы игры в проект не включены.

## Правила

- Источник плейлиста расположен непосредственно над проигрывателем.
- Блок должен входить в тег `minecraft:jukebox_containers`, а его block entity должен реализовывать контейнер.
- Для разновидностей ChestBlock дополнительно требуется тип `SINGLE`.
- Стандартный тег содержит обычный сундук, сундук-ловушку и восемь вариантов медного сундука.
- Пустой проигрыватель автоматически загружает первую доступную пластинку.
- Позиция — индекс слота сундука, из которого была взята предыдущая пластинка; начальная позиция отсутствует (`-1`).
- Поиск начинается со следующего слота, обходит контейнер по кругу и проверяет каждый слот не более одного раза.
- Текущая пластинка и содержимое найденного слота меняются местами. Это живая последовательность слотов, отдельной копии очереди нет.
- Если доступных пластинок нет, позиция сбрасывается; при естественном окончании текущая пластинка запускается снова.
- После извлечения пустой проигрыватель продолжает поиск со следующего слота. Извлечённая пластинка остаётся у игрока или выпадает обычным способом.
- Без допустимого контейнера проигрыватель работает по штатным правилам своей версии.
- Позиция сохраняется в `playlist_position`; длительность и состояние текущего трека сохраняет сама игра либо таймер адаптации старых версий.

## Границы API

| Версии | Адаптация |
| --- | --- |
| 1.16.5 | TickableBlockEntity; Forge сохраняет MCP-имена классов, Java 8 |
| 1.17–1.19 | Добавляется ticker; длительности ванильных треков и настраиваемые длительности других пластинок |
| 1.19.1–1.19.3 | Штатные `playRecordTick`, `getRecord`, `playRecord` |
| 1.19.4–1.20.2 | Контейнер с `getItem(0)` / `setItem(0, ...)` |
| 1.20.3–1.20.6 | Контейнер с `getTheItem` / `setTheItem`; в 1.20.5 добавляется registry provider при сохранении |
| 1.21–1.21.5 | JukeboxSongPlayer и компонент `jukebox_playable` |
| 1.21.6–1.21.10 | ValueInput / ValueOutput вместо прямого NBT API |
| 1.21.9 | Метод `Level.isClientSide()` |
| 1.21.11 | Identifier вместо ResourceLocation |
| 26.x | Имена классов без обфускации; игра использует Java 25; с 26.2 константы перенесены в BlockEntityTypes |

Мод использует существующие игровые пакеты запуска и остановки музыки. Обмен выполняется на серверном потоке.
В современных версиях сохраняются штатные события проигрывателя для редстоуна и слушающих музыку мобов.
Повтор после естественного окончания определяется переходом штатного таймера из воспроизведения в остановку.
Это сохраняет штатное поведение уже остановленной пластинки при последующей установке сундука.

Для безопасности переноса стопки из нескольких пластинок пропускаются: некоторые старые setters проигрывателя обрезают их до одного предмета.

Fabric Loom 1.13 переименовывает mixin-аннотации непосредственно в байткоде, без отдельного refmap
([официальная документация Loom](https://docs.fabricmc.net/develop/loom/options)).
Для старых Forge используется отдельная таблица refmap и переименование производственного JAR в SRG.
Добавленный ticker в 1.17–1.19 реализует интерфейс EntityBlock: это сохраняет переименование метода в производственной сборке.

## Адаптация LazoDiscs 1.0.7

Источник API: [LazoDiscs, ревизия 0c0d609](https://github.com/EyeCrasher07/LazoDiscs/tree/0c0d6096fb83331ef8ee7fb3829387e71a7909bf).
Это дополнение к механике снапшота: сам снапшот не содержит интеграции с LazoDiscs.

Запись распознаётся через `DiscDataUtil.hasCustomDisc`. Для её запуска используется `LazoDiscJukeboxAccess`,
который сохраняет исходный предмет и не включает параллельно ванильную музыку. На 1.19.4 и новее отдельно уведомляется
`JukeboxPlaybackManager`; ранние setters уже делают это сами.

Пока стоит запись LazoDiscs, штатный таймер ванильной пластинки пропускается. Переход привязан к `finishAt`
менеджера LazoDiscs после его проверки идентичности текущего источника и успешного удаления из `active`.
Затем на серверном потоке отсчитывается обычная пауза в 20 тиков и выполняется тот же обмен с сундуком.
Проверяется ссылка на завершившийся предмет: ручная замена во время паузы отменяет старый переход.
Ошибку загрузки LazoDiscs передаёт тем же callback; она не вызывает немедленный цикл повторных запросов.

Обмен переносит полный ItemStack. Данные LazoDiscs не пересоздаются, поэтому URL, UUID, название, громкость и радиус сохраняются.
После загрузки чанка или мира восстановлением своего звука занимается сам LazoDiscs; позицию очереди сохраняет Jukebox Playlists.
Проверки устаревшего источника LazoDiscs и наличия проигрывателя защищают от перехода после извлечения или разрушения блока.

Для опубликованных Fabric/Forge 1.16.5 предусмотрена узкая замена вызова форматирования координат в менеджере и аудиомосте LazoDiscs:
метод `BlockPos.method_23854` / `func_229422_x_` отсутствует на выделенном сервере. Это форматирование логов не меняет выбор трека.
Для Forge 1.21 необязательный Mixin-плагин добавляет LazoDiscs конструктор без аргументов, необходимый Forge 51.
Он делегирует исходному конструктору с текущим `FMLJavaModLoadingContext`; уже существующий конструктор без аргументов не заменяется.
Исходный файл LazoDiscs не изменяется.

Отдельно от мода предусмотрена утилита `tools/patch_plasmo_voice.py` для Forge 1.20.2:
она создаёт копию опубликованного PV 2.1.17, меняя только минимальные Forge/FML 49 на 48 и добавляя уведомление.
Диапазон Minecraft уже включает 1.20.2; классы и библиотеки не меняются. Оригинал проверяется по закреплённому SHA-512.
Этот вариант установки проверяется и отмечается отдельно от неизменённых зависимостей.

Интеграция загружается через необязательные mixin и отражение; исходники LazoDiscs и его библиотеки в мод не включаются.
